# Правила игры

## Подготовка
1. Игрок читает правила и вводит никнейм (2–24 видимых символа). Сервер устанавливает cookie браузера и допускает одну партию на установку.
2. Сервер случайно назначает одну из десяти компаний и фиксирует версию паспорта, движка, рейтинга и каталог карточек.
3. Игрок видит название, описание, публичные факты, метрики и утверждённый hero. Закрытые факты и внутренние параметры не показываются.

## Раунд
1. Игрок выбирает одну из четырёх предложенных карточек для текущего раунда и стартапа. Заголовок кратко называет приём атаки, описание объясняет конкретный сценарий.
2. Клиент отправляет только `choice_id`; API проверяет карточку в неизменном снимке сессии.
3. Сервер преобразует закрытые параметры карточки в прежний типизированный вход движка, рассчитывает до трёх месяцев и останавливается при непокрытых обязательствах.
4. Сервер синхронно сохраняет выбранную карточку, результат, месячный ledger и обновлённую сессию в одной транзакции. Результат отдельно показывает написанную реакцию команды и фактический защитный манёвр, если движок его выбрал. Повтор с тем же idempotency key возвращает сохранённый результат.
5. После результата игрок явно переходит к следующему раунду. Нельзя отправить новый выбор до завершения текущего.

## Баланс и завершение
Доступные действия, сильные и слабые варианты определены каталогом. Все суммы, защита, длительности, накопление эффектов и финалы следуют `ECONOMY.md`, `ENGINE_CONTRACT.md` и `SCORING.md`; тексты карточек сами по себе не меняют вычисления. Три раунда охватывают максимум девять месяцев. Банкротство завершает игру раньше. Финал — один из `survived`, `deep_crisis`, `near_bankruptcy`, `bankrupt`.

Каждая из десяти компаний использует v2: карточка имеет явный эффект, причинный переход и, при необходимости, prerequisite. Комбо срабатывает только после нужной цепочки; повторное появление карточки без prerequisite даёт только базовый эффект. Длительный эффект ослабевает по месяцам. У каждой стратегической защиты `max_uses=1` за игру; экстренное снижение затрат также одноразовое. Если все варианты ведут к банкротству, движок выбирает самый поздний месяц банкротства, затем меньшее число неоплаченных обязательств и большую накопленную выручку.

## Рейтинг
Только сервер считает результат по единой формуле 0–1000. Естественная базовая динамика не приносит очков. Равные результаты получают одинаковое место. Клиент не передаёт денежные значения или итоговые баллы.
