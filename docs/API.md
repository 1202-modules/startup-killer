# API — детерминированная игра

Базовый префикс `/api/v1`; JSON UTF-8, суммы в копейках, даты UTC. Мутации требуют same-site `Origin` и `X-CSRF-Token`; создание сессии, отправка выбора и продолжение также требуют UUID `Idempotency-Key`. Авторизация идёт через серверную `sk_browser` cookie (`HttpOnly`, `SameSite=Lax`, `Secure` в production). UUID сессии сам по себе не даёт доступ.

Ошибки имеют форму `{ "error": { "code", "message", "retryable", "details" }, "request_id" }`. Не отдавать скрытые факты, приватные параметры карточек или чужие сессии. Ручки состояний возвращают `Cache-Control: no-store`.

## Endpoints
- `GET /health/live` — `{"status":"ok"}`.
- `GET /bootstrap` — устанавливает/восстанавливает cookie, возвращает CSRF-токен и незавершённую сессию, если она есть.
- `GET /me/session` — ID и статус незавершённой партии браузера или null.
- `POST /sessions` — body `{"nickname":"..."}`; восстанавливает незавершённую партию или создаёт новую, в том числе после завершённых партий. Ответ включает только публичный профиль, состояние и карточки текущего раунда.
- `GET /sessions/{session_id}` — актуальное состояние, краткие результаты, `current_round_id`, `available_choices`, `can_attack`, `can_continue`, `completed`.
- `POST /sessions/{session_id}/choices` — body строго `{"choice_id":"..."}`. Дополнительные свойства запрещены. Успешный запрос синхронно возвращает результат раунда.
- `GET /rounds/{round_id}` — сохранённый результат только при владении сессией.
- `POST /sessions/{session_id}/continue` — переход к следующему раунду; идемпотентен.
- `GET /sessions/{session_id}/result` — финальные метрики и счёт завершённой сессии.
- `GET /leaderboard` — публичный рейтинг завершённых рейтинговых партий с ограниченной пагинацией.

## Публичная карточка
`id`, `round_number`, `title`, `short_description`, `attack_narrative`. Заголовок и конкретное объяснение удара берутся из самой карточки; разные варианты не объединяются по внутреннему типу атаки. `attack_narrative` сохраняет сюжетный контракт, но интерфейс не повторяет его, если он совпадает с описанием. Внутренние `attack_type`, severity/scale/feasibility, stream/fact/weakness IDs, защита, stack group и результаты остаются на сервере. Карточки сессии фиксируются при создании, чтобы последующее изменение общего каталога не меняло начатые партии.

В результате хода `defense.company_response` содержит заранее написанную реакцию команды выбранной карточки. `defense.type` и `defense.summary` отдельно показывают фактически выбранный движком защитный манёвр; значение `none` означает, что по текущей экономической формуле он невыгоден или недоступен.

## Идемпотентность
Сервер хеширует канонический `{choice_id}`. Повтор того же ключа и payload возвращает исходный результат; тот же ключ с другим payload получает 409. Другой ключ после обработки раунда не создаёт вторую проводку. Невалидный/чужой/не текущий выбор не меняет состояние.
