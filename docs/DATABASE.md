# Схема данных и миграции

PostgreSQL — production source of truth; SQLite используется локальными тестами. Основные таблицы: `browser_installations`, `startup_templates`, `startup_template_versions`, `game_sessions`, `game_rounds`, `monthly_ledger`.

## Сессия и каталог
`game_sessions` сохраняет cookie installation, выбранный startup/version и публичный исторический snapshot, состояние экономики, статус, текущий раунд, версии движка/рейтинга/каталога и `attack_choices_snapshot` из 12 внутренних карточек. Карточки фиксируются на старте сессии. API выдаёт только публичные поля.

`game_rounds` хранит round number, idempotency key и hash, `selected_choice_id`, внутренний `choice_snapshot`, статус resolved и сохранённый outcome. Не хранится свободный текст игрока, AI-анализ или provider provenance.

`monthly_ledger` — неизменяемые детальные проводки по каждому рассчитанному месяцу и ключевым параметрам результата. Уникальные ограничения защищают один раунд на номер и один ledger на месяц в сессии. Транзакция охватывает round, месяцы ledger и обновление session.

## Удалённые сущности
Runtime AI jobs, provider credentials, admin sessions/settings, usage events, ключи, запросы со свободным текстом и AI-ответы отсутствуют в актуальной схеме. Нет фоновой очереди или отдельного worker.

## Миграция 0002
`0002_deterministic_attack_choices` удаляет AI/admin таблицы и колонки свободного текста/анализа. Она стирает narrative/headline/circumstance поля старых ходов, которые могли содержать сгенерированный текст; завершённые финансовые итоги и месячные ledger сохраняются. Незавершённые старые раунды без рассчитанного ledger удаляются, а прерванные сессии возвращаются в готовое состояние без списания хода; каждой сессии назначается снимок текущего 12-карточного каталога.

Downgrade намеренно завершается ошибкой: удалённые секреты и сырой текст нельзя восстановить. Перед миграцией существующей БД нужен внешний проверенный backup; production миграция не выполнялась в рамках локальной проверки.

## Данные и индексы
Уникальность установки на сессию, `(session_id, round_number)`, `(session_id, idempotency_key)` и `(session_id, month_no)` сохраняет ограничения партии и ledger. Индекс рейтинга обслуживает только завершённые сессии. Закрытые weak-fact IDs не отправляются клиенту.
