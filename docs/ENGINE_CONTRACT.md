# Контракт детерминированного движка

API принимает публичный `choice_id`. Сервис разрешает его только в снимке карточек сессии, сверяет startup и номер раунда, загружает приватную версию паспорта и передаёт типизированный `ValidatedAttack` в существующий pure-Python движок. Других игровых входов от клиента нет.

Каталог фиксирует для каждого из 120 вариантов тип атаки, severity, scale, feasibility, target stream IDs, weakness/evidence IDs, duration, stacking group, сцену и заранее написанные narrative-поля. Catalog loader проверяет уникальность, число карточек, ссылки на стартапы/потоки/факты и согласованность weakness/attack type. Публичный DTO исключает все внутренние поля.

Экономический расчёт не меняется: целые копейки, Decimal/HALF_UP там, где предписано; формулы, месячные эффекты, защита, банкротство и рейтинг определяются `ECONOMY.md` и `SCORING.md`. Весь результат строится существующими `simulate_round` и `to_validated_attack`; не дублировать экономические формулы в API или UI.

Обработка выбора выполняется синхронно в транзакции. PostgreSQL блокирует строку сессии для сериализации конкурирующих выборов. Idempotency повторяет исходный round response; конфликт ключа/payload возвращает 409. История завершённых раундов восстанавливается через round endpoint или `current_round_id`.
