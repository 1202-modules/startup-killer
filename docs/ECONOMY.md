# ECONOMY.md — нормативная экономика

## v2: PetMind, CoffeeBot, FoodRover, StudyGenie

Для новых сессий этих четырёх компаний каталог `2.0.0-partial` задаёт явные `base_effect` и `combo`. Вся остальная часть этого документа описывает v1 и действует для шести остальных компаний, а также для старых снимков сессий.

- R1 устанавливает флаг своей цепочки. R2 применяет combo только при наличии флага R1 и только тогда устанавливает флаг для R3. R3 без флага R2 применяет base. Флаги хранятся в состоянии одной игровой сессии.
- Каждая стадия заменяет текущий эффект той же причинной группы целиком. Разные группы снижают остаток выручки мультипликативно; общая потеря потока ограничена 95%.
- Temporary действует максимум три месяца, каждый следующий месяц сохраняет 60% предыдущего эффекта. Persistent действует максимум шесть месяцев и сохраняет 85%. Structural действует до конца игры либо устранения причины. Первый месяц входит в срок.
- Базовая выручка каждого потока округляется до копейки `ROUND_HALF_UP` за месяц. После потерь фактическая выручка и переменные затраты округляются по потоку за месяц. Разовые инциденты указаны в копейках в каталоге, репутация не даёт второго денежного штрафа.
- Если одновременно действуют скидка защитного манёвра и аварийное сокращение, их коэффициенты выручки перемножаются перед месячным округлением.
- Защита выбирается по прогнозу от текущего состояния до месяца 9 без предположений о будущих атаках: сначала отсутствие банкротства, затем больше денег к месяцу 9, затем меньшая цена и стабильный порядок. Если все варианты банкротятся, раньше выбран тот, который откладывает банкротство. Цена списывается в текущем месяце, эффект начинается со следующего. Максимум один манёвр в раунд.
- Защита уменьшает только потери своей причинной группы. B-атаки R3 переводят техническую причину в уход клиентов; техническая защита не возвращает ушедших клиентов. Расходы и скидки уже запущенной защиты продолжаются в указанный срок.
- Аварийное сокращение доступно только если прогноз NONE приводит к банкротству, один раз за игру: цена 25% текущих фиксированных месячных затрат, со следующего месяца fixed −15% и вся выручка −5% до конца игры.
- `baseline_series` остаётся расчётом без атак и защит. Для каждого результата сравниваются фактические деньги и выручка с baseline того же месяца; естественная убыточность не считается ущербом игрока.

Утверждённые `finance_config` этих четырёх компаний не изменены. Их паспорт имеет версию 2, шесть остальных паспортов и их карточки остаются v1.

## 1. Инварианты

- Единый детерминированный движок для десяти заранее созданных паспортов из `data/startups.json`. Каталог карточек задаёт вход движка; тексты карточек не меняют числовые формулы, банкротство и очки.
- Партия: три раунда по три виртуальных месяца. После банкротства симуляция немедленно заканчивается.
- Деньги: integer копейки. Доли: basis points (10 000 = 100%). Промежуточные произведения — Python Decimal, ROUND_HALF_UP при фиксации месячной проводки.
- На старте каждого месяца `baseline_revenue(stream,m)=initial_revenue * (1+monthly_growth_bps/10000)^(m-1)`; округление по каждому источнику. Без атак фиксированные затраты неизменны, репутация неизменна, никаких новых инвестиций.
- `cash_close = cash_open + sum(actual_revenue_streams) - sum(actual_variable_cost_streams) - actual_fixed_cost - incident_cost - defense_cost`. При `cash_close<0`: cash=0, дефицит в `unpaid_obligations`, статус bankrupt; не создавать следующие месяцы.

## 2. Каноническая интенсивность

Из выбранной сервером карточки берутся только типизированные enum-параметры. `severity`: weak=1200, medium=3000, strong=5500, critical=8000 bps. `scale`: local=4000, regional=6500, company_wide=10000. `feasibility`: unsupported=5000, plausible=8000, established_in_state=10000. `weakness_match`: indirect=8000, normal=10000, exact=12500. `weakness_match` назначается СЕРВЕРОМ только по фактам/слабостям из закреплённого паспорта (клиент не передаёт множитель). Итог = произведение коэффициентов / 10000^3 с округлением HALF_UP в bps. Обычный cap отдельного источника 9500 bps. Угроза может быть критической, только если имеет подтверждённый механизм, прямую уязвимость и допустимые ресурсы; пустой `evidence_fact_ids` означает downgrade.

Карточка `absurd` не создаёт безусловный глобальный эффект: её зафиксированные типизированные параметры проходят те же ограничения severity, scale, feasibility и evidence, что остальные карточки. Полное отключение отдельного источника разрешено исключительно при конкретном подтверждённом прекращении его работы (например, невозможности заменить единственного поставщика), а не как общий cap bypass.

## 3. Классификация воздействия

- `competition|product|demand` — снижение спроса **только** на target_stream_ids.
- `supply|technology` — снижение доступности названного источника (выручка), опциональный однократный incident_cost только если в сценарии есть фактический простой/ремонт.
- `reputation` — падение спроса на подтверждённые потоки и отдельное отображение изменения репутации. Не применять репутационный множитель к выручке повторно: спрос уже учёл тот же кризис.
- `cost|finance` — подтверждённое увеличение fixed/incident costs вместо фиктивной потери всей выручки; если JSON не несёт достаточной детализации для числового расчёта, сервер использует утверждённый категорийный incident_cost и не меняет выручку без явного target stream.
- `absurd` — использовать только заранее выбранную экономическую категорию и параметры карточки; отдельной формулы для абсурдных событий нет.

Таблица однократных расходов при конкретном обоснованном cost/supply/technology/finance инциденте: weak=1500, medium=3500, strong=7000, critical=12000 bps от фиксированных месячных расходов **до защиты**. Умножить на scale и feasibility, но НЕ на weakness_match. Списать только в месяц инцидента. Для competition/demand/product дополнительных случайных расходов нет. Если тип репутационного кризиса требует возвратов, применять только при подтверждённом факте, единожды, по тому же enum-справочнику. Одно событие не должно начислять и incident_cost, и идентичный fixed_cost shock дважды.

Репутация: `weak -3`, `medium -8`, `strong -15`, `critical -24` умножить на scale и feasibility, HALF_UP до целого, clamp 0..100. Нерепутационная атака может менять репутацию только при отдельно подтверждённом репутационном последствии; по умолчанию 0. Репутация не является независимым денежным модификатором в MVP.

## 4. Сроки, наложение и история

`temporary`: стартовый множитель, decay 6000 bps на следующий месяц, максимум три месяца. `persistent`: decay 8500 bps, максимум 6 месяцев. `structural`: неизменный эффект до устранения механизма защитой; максимум девять игровых месяцев. Начало — в текущем месяце, кроме явно требующих подготовки конкурентных продуктов: запуск конкурента откладывается на один месяц, если факт существования готового продукта отсутствует в игровой истории.

Эффекты одного `stack_group` и `target_stream_id` в рамках повторённой угрозы объединяются через `max(existing,new)`, не сумму; длина продлевается только при новой доказанной причине. Разные независимые эффекты на источнике: `remaining_revenue = baseline_revenue * product(1-effect_i)`; суммарная потеря <=100%. Для cost-shock повтор идентичного инцидента не создаёт вторую разовую проводку без новой подтверждённой причины.

После каждого месяца сначала вычисляется эффект на каждый поток, затем затраты, затем cash. Защита применяется только по правилам п.5. Ledger хранит использованные компоненты и остаток по каждому месяцу.

## 5. Защитные действия — один манёвр в раунд

Для каждого доступного манёвра сервер строит детерминированный прогноз оставшихся месяцев **текущего раунда**, включая `none`; выбирает максимальный `cash_close`, при равенстве меньший разовый платёж, затем enum order. Если защита в ходе трёх месяцев требует больше денег, чем есть на момент оплаты — не выбирать. В прогнозе не считать будущие неизвестные атаки.

- `none`: цена 0, эффекта нет.
- `cost_cut`: цена 2500 bps текущих fixed costs единожды; со следующего месяца fixed -15% и вся выручка -5% (операционные сокращения). Только один раз за партию.
- `pr`: цена 2500 bps current fixed, со следующего месяца восстанавливает 30% утраченной из-за подтверждённого reputation-crisis выручки, максимум три месяца. Без кризиса недоступна.
- `supplier_switch`: цена 4500 bps fixed, задержка 1 месяц, снимает 70% supply-interruption с затронутого потока; variable-cost-bps этого потока +400; только при наличии подтверждённой альтернативы в private_profile.
- `pivot`: цена 7000 bps fixed, два месяца подготовки, затем новый источник с выручкой не более 15% начальной выручки компании, с weighted variable-cost-bps компании; нужен совместимый актив из private_profile. Один раз за партию; запуск после задержки, не сразу.

Наличие манёвра в `allowed_defenses` НЕ означает доступность: нужны деньги, время, ресурс и актуальная причина. Использование фиксируется в `used_defenses`. Защиту детерминированно выбирает сервер по доступности и прогнозу экономики.

## 6. Baseline и версии

`baseline_series` вычислена по этим правилам **без атак и защит** и хранится в immutable версии каждого паспорта. `data/startups.json` содержит месяцы 0..9. Если движок меняется, выпустить новую версию экономики и пересчитать baseline для НОВЫХ партий; текущие не перезаписывать. Не менять таблицу результатов задним числом.

## 7. Отдельный обязательный проверочный вопрос перед кодом

Карточки `cost|finance` используют только фиксированные категорийные одноразовые инциденты как определено выше; они не задают произвольные числовые изменения fixed cost или долга. Структурная долговая модель требует отдельной версии экономики и согласования.
